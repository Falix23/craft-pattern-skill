# 配置与图纸格式

用户给图片要求直接返回图纸或多方案时，使用 `scripts/generate.py`，详见[直接出图协议](direct-output.md)。它支持自动提色并输出 PNG/SVG/CSV/JSON，无须网页；下述构建配置专指 `build.py` 的显式色板 HTML 工作流。两种工作流共用 version 2 图纸格式。

## Python 构建配置

配置示例见 `examples/input.json`。旧配置仍可构建，省略新参数时使用下表默认值。

| 字段 | 含义与约束 | 默认值 |
| --- | --- | --- |
| `title` | 图纸标题 | `手工图纸` |
| `image` | 相对配置文件目录的本地图片；`--image` 覆盖路径相对当前工作目录 | `demo.png` |
| `width` / `height` | 各 4–160 的整数格数 | 各 `40` |
| `mode` | `bead` 或 `cross-stitch`，共用格子数据 | `bead` |
| `fit` | `contain` 等比完整保留并留边，或 `cover` 等比居中裁切 | `contain` |
| `palette` | 2–36 个 `{id,hex}`，必填；`id` 唯一非空，`hex` 为 `#RRGGBB` | 无 |
| `background` | `transparent` 保留透明与透明留边；`auto` 另去外围纯色背景；`keep` 透明与留边合白并全部配色 | `transparent` |
| `background_tolerance` | 去底 RGB 欧氏距离容差，整数 0–120，仅 `auto` 使用 | `32` |
| `alpha_threshold` | 小于此值的 alpha 视为留空，整数 1–255 | `128` |
| `cleanup` | 整数 0–4：0 关闭；1–3 近色小块清理；4 拼豆优先，区域整理与细节采样 | `build.py` 省略为 `1`；页面新图片与 `generate.py` 为 `4` |
| `color_detail` | 颜色区分度：`low` 低、`medium` 中、`high` 高；控制页面自动提色与近色合并，CLI 显式色板保持原样 | `medium` |

图片不得超过 4000 万像素。Python 使用 Pillow 支持的图片格式，先校正 EXIF 朝向，按 `fit` 使用 LANCZOS 缩放，再处理背景、映射色板和清理杂色。最近色映射使用 Oklab 距离并额外惩罚有彩色之间的色相偏移，避免淡黄色因亮度接近而映射成粉色，或暗红、蓝色填充偏配到黑色。清理强度 1–3 仍使用原有线性 RGB 加权阈值。色值为屏幕 RGB 参考，材料统计仅记录各色所需颗数。

`auto` 在目标格 RGBA 上按 alpha 得到有效区域包围盒，采样其外围，将 RGB 各通道按 16 分档。最多颜色档占有效外围样本至少 35% 时，取该档均值作为背景参考；随后仅删除颜色距离在容差内、与图边或透明格四邻连通的区域。封闭的同色细节可保留。这是针对外围纯色背景的连通算法，并非主体识别或语义抠图。

杂色清理只处理不接触图边或空格的小连通色块，要求外围四邻接边至少 75% 投向同一其他颜色，且线性 RGB 加权距离不超过 `0.035`（强度 3 为 `0.06`）。替换一次完成、不迭代、不填充空格，避免连续侵蚀轮廓。

上述小块规则适用于强度 1–3。强度 4 是拼豆优先：先在最长边不超过 1024 的源图上去底，再重采样，避免背景与轮廓混合成灰色材料。源图外围浅中性灰按共同背景分组；参考平均亮度至少 150、通道跨度不超过 24 时，允许与外围连通的有限中性阴影。候选平均亮度至少 140，亮度差不超过 `min(64, 容差×1.75)`，中心化通道差不超过 `max(8, 容差×0.45)`；容差 0 关闭扩展。仍是颜色与连通性去底，不是语义主体分割。

强度 4 使用宽高各 6 倍的采样副本（底层采样函数也兼容旧的 3× 数据）。先在 Oklab L 上做灰度闭运算，取闭运算减原图的黑帽响应，寻找紧凑暗线；再用 Sobel 梯度的 3×3 结构张量最小特征值（Shi–Tomasi 响应）筛选有结构支持的区域。这是参考[形态学黑帽](https://docs.opencv.org/4.x/d9/d61/tutorial_py_morphological_ops.html)和[Shi–Tomasi](https://docs.opencv.org/4.x/d4/d8c/tutorial_py_shi_tomasi.html)的自定义实现，不依赖 OpenCV、模型文件或神经网络，没有调用完整的 `goodFeaturesToTrack()` 接口，也不是人脸识别器。

暗线候选要求黑帽差值至少 0.09、L<0.62、角点响应至少 0.0005，按八连通性提取区域。拒绝单点、过大区域、接触透明轮廓较多的区域和含封闭孔洞的环形轮廓，避免把彩色球体重新涂黑。每个区域投影至目标格时按覆盖量限制格数，并在源图已有间隔、目标格能表达时保留不同短线之间的间隔；不删除某个特征的最后一个锚点来强造间隔。仅在目标格 L≥0.55 且原图短线比该格暗至少 0.1 时按覆盖量做有限颜色增强，避免把人像原有暗面继续压黑；不会把所有角点直接改成最暗色。未命中特征的格子继续用 3×3 颜色样本组恢复有支持的彩色填充或紧凑短暗线。采样只修改颜色，不改变 alpha 和主体占位；这是传统局部结构提取，不会语义识别人脸或补画原图不存在的五官。

### 纯色插画的区域采样与短线重建

`generate.py` 与页面编辑器共用 `PatternCore.flatCraftRGBA`。清理强度 4 时，先分析 6× 副本中的四邻域：至少三邻与该像素的 Oklab 距离小于 0.025，视为稳定纯色样本。稳定样本占有效像素至少 72%、得到的紧凑色板不超过八色且有足够明暗差异时，使用区域采样；否则沿用上述局部特征流程。

自动色板从稳定样本提取，在较小色差范围整理同一填色和描边的细微变化，不强制凑满颜色数；显式用户色板的色号、颜色与顺序保持不变。源图先映射成色区标签，再按每格覆盖量投票，不将黑边与白/棕填充的平均色直接变成新材料。透明占位仍严格取原始目标格 alpha，不扩充或删除主体格。

小暗色连通笔画只在单一稳定浅色邻区中重建；封闭孔洞、大块阴影、粗色块和接触空白的轮廓会排除。用横/纵游程的中心线轮廓及弯折，配合 [Douglas–Peucker 折线简化](https://docs.opencv.org/4.x/dd/d49/tutorial_py_contour_features.html)得到紧凑路径，再投影到格子。弯曲短线保留最低限度的二维跨度，在原位置一格邻域内选择不覆盖腮红等颜色、不与另一笔画粘连的对齐方式。少量局部夸张和位移是为低格数表达表情的像素化取舍，不代表原像素逐点保真，也不是语义识别人脸或手工套用眼睛模板。

`build.py` 用显式色板构建的初始图仍采用 Pillow 的原有 RGBA 采样；其内嵌页面重新生成时使用共享区域流程。要准确保留直接生成的区域图，保存并导入该方案 JSON，不重新采样。


区域整理最多两轮，每轮构建四连通区域及邻接边界。小区域上限为 `clamp(round(格位数×0.003), 4, 12)`，仅并入至少 8 格且不少于自身 3 倍的邻区，邻接票数至少 50%。用 Oklab 色差、暗色细节和高彩度点缀保护约束合并；色度至少 0.03 且与邻区有明显色相差异（15 度以上，或邻区为低彩度色）的点缀也保留，防止淡粉腮红、唇色因面积小被抹掉；轮廓碎色可并入相近主体色，封闭深色区域里的微小中性灰斑可适当简化。整理只重着色，不填空、不删主体格。极小浅色标记可能消失，需检查实际图案；纯像素图可选 0–3 保留原设计。

源图成功去底后，目标格的提色、配色及清理前对比仅保留透明区域，不再次识别背景，避免高分辨率下将贴图边的深色主体误删。源图未能识别任何背景时，保留目标格去底回退；图纸元数据仍记录用户选择的原始处理参数。

页面新图片默认“拼豆优先”和最多 8 色，可调整到 2–36 色。自动提色会再协调一次合并后代表色，避免显示出来的近似黑色仍被拆开。

## 浏览器图片转换

“图纸分辨率”控制实际的 `width/height`，滑杆和预设调整最长边；保持比例时以原图比例联动，解锁后允许分别输入宽高。改动参数后点击生成才重新采样源图并保存新版本；“待生成”格位数不是最终用豆数，空格仍不计材料。“预览缩放”只影响显示像素大小，不改变图纸数据。

页面可选择或拖入 PNG、JPEG、WebP、GIF 首帧或 AVIF，解码以浏览器支持为准；限制为 20×1024×1024 字节和 4000 万像素。页面在本地将原图预览缩到最长边 1024，再用 Canvas 缩到目标格。启用本地服务时，图纸和源图经 `127.0.0.1` 保存到本机案例库，不发送至外部服务器。

新图片加载后默认自动提取最多 2–36 色通用 RGB 色板（`AUTO01` 等）并生成图纸，也可沿用当前图纸色板。原图配色是受颜色数量上限约束的量化近似。每个色号旁的“调色”提供原生颜色选择器、HEX 输入和常用色块，确认后仅替换该色号的 `hex`，不改动格子索引、留空或用豆数；换色可撤销/重做，并随 JSON、SVG、CSV 和案例版本保存。自定义后生成模式切到沿用当前色板，避免随后生成直接覆盖选色；切回自动提色可从原图重新提色。

自动提色不是品牌色号匹配；`build.py` 始终使用配置中的显式色板，`generate.py` 默认调用页面同一份 PatternCore 自动提色，也可传显式色板。背景、最近色映射和杂色清理的规则在两端一致，但浏览器解码、Canvas 缩放、预览缩放与 Pillow LANCZOS 的采样和取整可能不同。同一原图在页面重新生成时，边缘或细节格可能与 Python 初始结果略有差异；需要保留结果时保存图纸 JSON。

中档自动提色在量化后，以 Oklab 欧氏距离不超过 `0.075` 为手工简化容差合并近似色。这是本项目的实用阈值，不代表品牌材料的色差标准。每个合并组内任意两种原色都必须满足容差，避免沿渐变链条将深浅层次全部吞并；新 RGB 参考值按量化样本数量加权。当前图纸的“合并近似色”用同一规则，按实际用豆数加权并重映射索引，保留空格和总颗数，可撤销。沿用用户色板的重新生成不会自动合并自定义色号。单色结果保留一个未使用的对比备用色以满足现有 2–36 色协议。

自动提色先按 Oklab 色相的 30 度分区和 `L=0.5` 的明暗分界建立候选组，再分配剩余量化预算；低彩度点归入中性色组。先以最多 `min(36, 颜色上限×3)` 个候选色量化；候选组较多时结合感知色差与样本量分配位置，剩余样本分配至最近组。两次近色合并后，再按与已选色的最小 Oklab 色差乘以样本量平方根选择实际色板。已有至少三色后，对有足够样本支持、亮度和色度较高的独立色相加权，避免黄色腮红等小区域被多个同色相阴影挤掉；严格保持用户颜色上限。这样小面积粉色爱心不会在最初的 RGB 分组中直接平均进大面积棕色，深色轮廓也不会与明亮点缀混成一色。近色合并时，双方色度均至少 `0.025` 时，以 15 度色相差为界保持明显不同的颜色分开；两轮代表色合并均遵循这一约束，防止不同色相的点缀被吞并。

近黑色另按材料档位处理：Oklab `L≤0.32` 且色度 `C≤0.035` 的低彩度深色在自动提色和“合并近似色”时归为同组，避免 `#121419`、`#2B2625` 等阴影差异额外占用材料。分组采用绝对边界，不沿灰阶不断扩张，深蓝、深红与中灰仍按原有色差规则判断。显式容差 0 关闭这项合并；手动调色不会强制重写用户选色。

“颜色区分度”提供低/中/高三档，Oklab 合并容差分别为 `0.11 / 0.075 / 0.035`。低档的低彩度近黑档边界为 `L≤0.36, C≤0.04`，中档沿用 `L≤0.32, C≤0.035`，高档关闭近黑强制归档以保留阴影层次；三档都使用上述色相保护边界，保留明显不同的点缀。颜色数仍受“最多颜色”上限约束，原图本来就只有几种明显颜色时，低/中两档可能得到相同色数。该参数与空间碎色清理独立。

切换档位后需点击生成；有原图时自动切换到原图提色，以恢复先前已合并的色差。无原图的图纸可按所选档位“合并近似色”，恢复更多层次需补原图。档位保存于 `processing.color_detail`，随 JSON、案例版本和整库备份保留；旧图纸缺省按中档处理。手工合并的参数变化与色板一起支持撤销，保持占位、空格和总颗数不变。

点击色板色号会在画布中用 1 像素玫红线与细白色衬边勾勒同色区域轮廓，仅描绘与其他颜色、空格或画布边缘相邻的边，区域内部不重复框格，分散区域分别圈出；状态栏显示匹配格数并提供取消。标记随切色、缩放、绘制和历史恢复更新，新图纸/导入/打开案例会清除。它不修改数据、不触发归档，预览归档、SVG、JSON、CSV 和打印均不包含高亮。

## 图纸 JSON：version 2

页面导入的是以下图纸格式，不是带 `image` 的原图配置。兼容导入旧版 `version:1`（只能有色号索引），导入后规范化为 version 2；旧图纸色板中额外的 `stock` 字段会被忽略。图纸 JSON 不超过 5,000,000 字节。

| 字段 | 内容 |
| --- | --- |
| `version` | 新输出为 `2` |
| `title` / `mode` / `width` / `height` / `palette` | 标题、模式、尺寸和色板，约束同上 |
| `cells` | 行优先数组，长度为 `width×height`；每项为 `null`（不放豆子的空格）或 `palette` 的 0 起始整数索引 |
| `source` | `{name,fit}`，记录原图文件名及适配方式 |
| `processing` | 实际采用的 `background`、`background_tolerance`、`alpha_threshold`、`cleanup`、`color_detail` |
| `metrics` | `blank_cells` 空格数、`bead_count` 实际用豆数、`removed_background` 本次生成去掉的背景格数、`cleaned_cells` 本次生成合并的杂色格数 |
| `notes` | 字符串说明数组 |

编辑后空格与用豆数随图纸更新，去底和清理数保留最近一次生成的记录。JSON 不含原图，也不保存撤销历史。单独导入 JSON 后可继续逐格编辑，重新生成需要重新选择对应原图；从案例库打开有源图的版本可直接恢复。Python 构建的 HTML 自带内嵌脚本、样式及原图预览，可以离线调整设置；构建旁路 JSON 是初始图纸，页面修改可归档到案例库，或点“保存图纸”另存 JSON。

## 构建与案例归档

`python scripts/build.py <config.json> --output <pattern.html>` 默认将构建结果、规范化源图和预览自动收录到用户 SQLite 库；`--library <目录>` 覆盖目录，`--no-archive` 仅构建，`--case-id <ID>` 给已有案例追加版本，`--tags "标签一,标签二"` 设置案例标签。内部 Python `build()` 只构建 HTML/JSON，不自动归档，供测试和示例生成使用。

图纸 JSON 与整库备份是不同格式。案例元数据、版本、SQLite/IndexedDB 存储、CLI 检索及备份协议见[案例库协议](library.md)。生成、导入图纸 JSON 和导出保存 JSON 会自动归档；画笔等手工修改可用“保存新版本”归档。直接打开 HTML 时使用当前浏览器的 IndexedDB；本地服务连接 SQLite。两者相互独立，需要导出/导入整库备份才能迁移。

SVG 空格 `fill="none"`，保留辅助网格；材料 CSV 与用豆统计跳过空格。SVG 每格 5 mm 是图纸标注比例，实际手工尺寸需另据材料颗粒间距或布料针数计算。打印调用浏览器打印功能，大图分块由打印软件处理。
